## 클러스터 아키텍처

### 컨트롤러

#### 컨트롤러 패턴

##### 직접 제어

Job과는 반대로, 일부 컨트롤러들은 클러스터 바깥에서 변경을 가한다.

예를 들어, 클러스터에 충분한 [Node][k8s-concepts-architecture-nodes]가 있도록 하는 제어 루프를 사용한다면, 이 컨트롤러는 필요할 때 새 Node를 셋업하기 위해 현재 클러스터 바깥의 무언가가 필요하다.

외부 상태와 상호작용하는 컨트롤러는 API 서버로부터 자신의 원하는 상태를 찾는다. 그 다음 외부 시스템과 직접 통신해 현재 상태를 더 가깝게 만든다.

(실제로 클러스터에서 노드를 수평적으로 확장하는 [컨트롤러][github-k8s-autoscaler]가 있다.)

여기서 중요한 점은 원하는 상태로 만들기 위해 컨트롤러가 변경을 가하고 현재 상태를 클러스터의 API 서버에 보고한다는 점이다. 다른 제어 루프는 보고된 데이터를 관측하고 각자의 행동을 한다.

온도조절기 예시에서 방이 너무 차가우면 다른 컨트롤러는 결빙 방지 히터를 켤 수도 있다. Kubernetes 클러스터에서 컨트롤 플레인은 IP 주소 관리 도구, 스토리지 서비스, 클라우드 제공자 API 및 [Kubrentes 확장][k8s-concepts-extend-kubernetes]을 구현하는 다른 서비스와 간접적으로 동작한다.
