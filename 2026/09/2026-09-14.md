## 개요

### kubectl 커맨드 라인 도구

#### kubectl은 어떻게 동작하는가

`kubectl` 도구는 [kubeconfig][k8s-concepts-configuration-organize-cluster-access-kubeconfig] 파일에 정의된 클러스터, 사용자, 컨텍스트를 사용해 API 서버에 연결해 인증한다. 클러스터 외부에서 `kubectl`을 실행하면 kubeconfig 파일을 사용해 API 서버 주소와 크리덴셜을 찾는다. `kubectl`을 (CI/CD 파이프라인과 같은)Pod 내부에서 실행하면 Pod에 마운트된 ServiceAccount를 기반으로 클러스터 내 인증을 사용할 수 있다.

커맨드를 실행하면 `kubectl`은 여러분의 의도를 [Kubernetes API][k8s-concepts-overview-kubernetes-api]에 대한 하나 이상의 HTTP 요청으로 변환한다. API 서버는 각 요청의 유효성을 검증하고 [etcd][k8s-tasks-administer-cluster-configure-upgrade-etcd]에 저장된 클러스터 상태에 적용한 다음 결과를 반환한다. 즉,  Deployment를 만들든 로그를 읽든 모든 `kubectl` 동작은 동일한 API 주도 경로를 따른다.

kubeconfig는 여러 클러스터, 사용자, 컨텍스트를 정의할 수 있기 때문에 `kubectl`을 사용해 환경을 재구성하지 않고도 클러스터 사이를 전환할 수 있다. 활성화된 컨텍스트를 바꾸려면 `kubectl config use-context`를 사용한다.
