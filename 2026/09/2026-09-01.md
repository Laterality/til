## 개요

### Kubernetes API

Kubernetes [컨트롤 플레인][k8s-reference-glossary-control-plane]의 핵심은 [API 서버][k8s-concepts-architecture-kube-apiserver]다. API 서버는 최종 사용자, 클러스터의 서로 다른 부분들, 외부 컴포넌트가 서로 통신할 수 있게 한다.

Kubernetes API는 Kubernetes의 API 객체(예: Pod, Namespace, ConfigMap, Event)의 상태를 쿼리하고 조작할 수 있게 한다.

대부분의 작업은 [kubectl][k8s-reference-kubectl] 커맨드 라인 인터페이스나 [kubeadm][k8s-reference-setup-tools-kubeadm]과 같이 API를 사용하는 다른 커맨드 라인 도구를 통해 수행된다. 하지만 REST 호출을 사용해 API에 직접 접근할 수도 있다. Kubernetes는 Kubernetes API를 사용하는 애플리케이션들을 위해 [클라이언트 라이브러리][k8s-reference-using-api-client-libraries] 집합을 제공한다.

각 Kubernetes 클러스터는 클러스터가 제공하는 API 명세를 게시한다. Kubernetes가 API 명세를 게시하는 데 사용하는 메커니즘은 두 가지가 있다. 둘 다 자동 상호운용성을 가능케 하는 데 유용하다. 예를 들어, `kubectl` 도구는 커맨드 라인 완성과 다른 기능들을 위해 API 명세를 인출해 캐싱한다. 지원되는 두 메커니즘은 다음과 같다:

- [디스커버리 API][k8s-concepts-overview-kubernetes-api-discovery-api]는 API 이름, 리소스, 버전, 지원되는 작업과 같은 Kubernetes API에 관한 정보를 제공한다. Kubernetes OpenAPI와는 별개의 API이기 때문에 이는 Kubernetes에 특화된 용어다. 사용 가능한 리소스들의 짧은 요약을 제공하기 위한 것으로 리소스의 상세 스키마는 제공하지 않는다. 리소스 스키마의 레퍼런스는 OpenAPI 문서를 참고하라.
- [Kubernetes OpenAPI 문서][k8s-concepts-overview-kubernetes-api-openapi-interface-definition]는 모든 Kubernetes API 엔드포인트에 대한 (완전한) [OpenAPI v2.0과 3.0 스키마][openapis-org]를 제공한다. OpenAPI v3가 API에 대한 더 포괄적이고 정확한 뷰를 제공하므로 OpenAPI에 접근하는 데 선호되는 방법이다. 사용 가능한 모든 API 경로들을 포함하고 있을뿐만아니라 모든 엔드포인트의 모든 작업에서 소비되고 만들어지는 모든 리소스들도 포함한다. 또한 클러스터가 지원하는 광범위한 컴포넌트도 포함한다. 데이터는 완전한 명세이며 디스커버리 API보다 훨씬 크다.
