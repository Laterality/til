## 개요

### Kubernetes API

#### 영속성

Kubernetes는 객체의 직렬화된 상태를 [etcd][k8s-tasks-administer-cluster-configure-upgrade-etcd]에 저장한다.

##### API 그룹과 버저닝

필드를 제거하거나 리소스 표현을 재구조화하는 것을 쉽게 만들기 위해, Kubernetes는 `/api/v1`, `/apis/rbac.authorization.k8s.io/v1alpha1`처럼 각각을 다른 API 경로로 여러 API 버전을 지원한다.

버저닝은 리소스나 필드 수준 대신 API 수준에서 이루어져 API가 시스템 리소스와 동작을 명화하고 일관된 뷰로 제공하도록 하며 수명이 다했거나 실험적인 API에 대한 접근을 제어할 수 있게 한다.

API를 발전시키고 확장하기 쉽게 만들기 위해, Kubernetes는 [활성화하거나 비활성화][k8s-reference-using-api-enabling-or-disabling]할 수 있는 [API 그룹][k8s-reference-using-api-api-groups]을 구현한다.

API 리소스는 자신의 API 그룹, 리소스 유형, (네임스페이스에 속하는 리소스인 경우)네임스페이스, 이름으로 구분된다. API 서버는 API 버전 간의 변환을 투명하게 처리한다. 모든 서로 다른 버전들은 실제로는 영속화된 같은 데이터에 대한 표현들이다. API 서버는 여러 API 버전들을 통해 같은 기반 데이터를 제공할 수 있다.

예를 들어, 같은 리소스에 두 API 버전 `v1`과 `v1beta`이 있다고 하자. 처음 객체를 `v1beta` 버전의 API를 사용해 만들었다면, `v1beta1` 버전이 폐기(deprecated)되거나 제거될 때까지 `v1beta`이나 `v1`  API 버전 중 하나를 사용해 객체를 읽고, 갱신하고, 삭제할 수 있다. 이 때 `v1` API를 사용해서 객체에 접근하고 갱신을 계속할 수 있다.
