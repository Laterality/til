###### API 변경

성공적인 시스템은 새로운 유스 케이스나 기존의 것들이 변경됨에 따라 성장하고 바뀌어야 한다. 따라서 Kubernetes는 Kubernetes API가 지속적으로 바뀌고 성장하도록 설계했다. Kubernetes 프로젝트는 기존 클라이언트와의 호환성을 깨지 *않*고 일정 기간동안 호환성을 유지해 다른 프로젝트들이 적응할 기회를 갖도록 하는 데에 초점을 맞춘다.

일반적으로, 새 API 리소스와 새 리소스 필드는 자주 추가될 수 있다. 리소스나 필드의 제거는 [API 폐기 정책][k8s-reference-deprecation-policy]을 따라야 한다.

Kubernetes는 공식 Kubernetes API가 주로 API 버전 `v1`인 일반 사용 가능(GA)에 도달하면 이를 유지하기 위해 노력한다. 추가로, Kubernetes는 공식 Kubernetes  API의 *베타* API 버전을 통해 영속화된 데이터와의 호환성을 유지하며 이 데이터는 기능이 안정화되면 GA API 버전들을 통해 변환과 접근이 가능하다.

베타 API 버전을 채택할 경우, API가 발전하면 후속 베타나 안정 API 버전으로 전환해야 할 것이다. 객체는 두 API 버전들을 통해 동시에 접근 가능하므로 전환을 위한 적절한 시점은 베타 API가 폐기 기간에 있을 때다. 베타 API가 완전히 폐기되면 더이상 제공되지 않으며 대체 API 버전을 사용해야 한다.

> [!NOTE]
>
> Kubernetes는 *알파* API 버전과의 호환성도 유지하는 데 초점을 맞추지만, 어떤 경우에는 이것이 불가능할 수 있다. 알파 API 버전을 사용할 경우, 업그레이드 전에 API가 호환되지 않게 변경돼 기존 알파 객체를 삭제해야 하는 경우를 대비해 클러스터를 업그레이드할 때 Kubernetes 릴리즈 노트를 확인하라.

API 버전과 수준의 정의는 [API 버전 레퍼런스][k8s-reference-using-api-api-versioning]를 참고하라.
