## 클러스터 아키텍처

### 노드

#### 관리

##### 노드의 자체 등록

kubelete 플래그 `--register-node`가 참(기본값)이면, kubelet은 자신을 API 서버에 등록하려고 시도한다. 이는 대부분의 배포판에서 쓰이는 선호되는 패턴이다.

자체 등록을 위해 kubelet은 다음 옵션들과 함께 시작된다:

- `--kubeconfig` - 자신을 API 서버에 인증하기 위한 크리덴셜 경로
- `--cloud-provider` - 자신에 관한 메타데이터를 읽기 위해 [클라우드 제공자][k8s-reference-glossary-term-cloud-provider]와 통신하는 방법
- `--register-node` - 자동으로 API서버에 등록한다.
- `--register-with-taints` - 노드를 지정된 목록의 [테인트][k8s-concepts-scheduling-eviction-taint-and-toleration]와 함께 등록한다(`<key>=<value>:<effect>`를 쉼표로 구분한다). `register-node`가 거짓이면 아무 동작도 하지 않는다.
- `--node-ip` - 선택사항, 쉼표로 구분된 노드를 위한 IP 주소 목록. 각 주소 패밀리마다 하나의 주소만 지정할 수 있다. 예를 들어, 단일 스택 IPv4 클러스터에서는 kubelet이 노드에 사용해야 하는 IPv4 주소를 설정한다. 듀얼 스택 클러스터 실행에 관한 자세한 내용은 [IPv4/IPv6 듀얼 스택 구성][k8s-concepts-services-networking-dual-stack-configure-ipv4-ipv6-dual-stack]을 참고하라.

    이 인자를 제공하지 않으면 kubelet은 노드의 기본 IPv4 주소를 사용한다. 노드가 IPv4 주소를 가지고 있지 않으면 kubelet은 노드의 기본 IPv6 주소를 사용한다.
- `--node-labels` - 노드를 클러스터에 등록할 때 추가할 [라벨][k8s-concepts-overview-working-with-objects-labels]([NodeRestriction admission 플러그인][k8s-reference-access-authn-authz-admission-controllers-noderestriction]에 의해 적용되는 라벨 제한을 참고하라).
- `--node-status-update-frequency` - kubelet이 얼마나 자주 API 서버에 노드 상태를 보낼지 지정한다.

[Node 인가 모드][k8s-reference-access-authn-authz-node]와 [NodeRestriction admission 플러그인][k8s-reference-access-authn-authz-admission-controllers-noderestriction]이 활성화된 경우, kuebelet은 자신의 Node 리소스에 대한 생성/변경만 허용된다.

> [!NOTE]
>
> [노드 이름 유일성][k8s-concepts-architecture-nodes-node-name-uniqueness] 섹션에서 언급된 대로, Node 구성이 갱신돼야 할 때는, 노드를 API 서버에 다시 등록하는 것이 좋은 관습이다. 예를 들어, kuebelt이 새로운 `--node-labels` 집합과 함께 재시작중인데 같은 Node 이름이 쓰이면 라벨은 Node 등록 시에만 설정되기 때문에 변경이 효과가 없다.
>
> Node 구성이 kuebelet 재시작 시 변경되면 이미 Node에 스케줄된 Pod들은 오동작하거나 문제를 일으킬 수 있다. 예를 들어, 이미 실행중인 Pod는 Node에 새로 할당된 라벨에 대해 테인트될 수 있는 반면 해당 Pod와 호환되지 않는 다른 Pod들은 새 라벨에 따라 스케줄될 수 있다. Node 재등록은 모든 Pod들이 드레인되고 적절히 다시 스케줄되도록 한다.
