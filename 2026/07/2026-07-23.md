## 개요

### Kubernetes의 객체

#### 라벨과 선택자

##### API

###### LIST와 WATCH 필터링

**list**와 **watch** 작업의 경우, 라벨 선택자를 명시해 반환되는 객체의 집합을 필터링할 수 있다. 쿼리 파라미터를 사용해 필터를 명시한다. (Kubernetes의 watch에 대한 자세한 내용은 [효율적인 변경 감지][k8s-reference-using-api-api-concepts-efficient-detection-of-changes]를 참고하라). 두 요구사항 모두 허용된다(URL 쿼리 문자열에 나타내는 것처럼 표기한다):

- *동등성-기반* 요구사항: `?labelSelector=environment%3Dproduction,tier%3Dfrontend`
- *집합-기반* 요구사항: `?labelSelector=environment+in+%28production%2Cqa%29%2Ctier+in+%28frontend%29`

두 라벨 선택자 스타일 모두 REST 클라이언트를 통해 리소스를 list나 watch하는 데 사용할 수 있다. 예를 들어, `kubectl`로 `apiserver`를 대상으로 하고 *동등성-기반*을 사용한다면 다음과 같이 쓸 수 있다:

```bash
kubectl get pods -l environment=production,tier=frontend
```

혹은 *집합-기반* 요구사항을 사용해:

```bash
kubectl get pods -l 'environment in (production),tier in (frontend)'
```

이미 언급했듯 *집합-기반* 요구사항은 더 표현력이 풍부하다. 예를 들어, 값들에 대한 *OR* 연산자를 구현할 수 있다:

```bash
kubectl get pods -l 'environment in (production, qa)'
```

혹은 *notin* 연산자를 사용해 음성 일치를 제한할 수도 있다:

```bash
kubectl get pods -l 'environment,environment notin (frontend)'
```
