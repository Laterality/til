### Kubernetes의 객체

#### 라벨과 선택자

##### 효율적으로 라벨 사용하기

하나읠 라벨을 어느 리소스에든 적용할 수 있지만, 이것이 항상 모범 사례는 아니다. 구분되는 리소스마다 여러 라벨을 사용해야 하는 많은 시나리오가 있다.

예를 들어, 서로 다른 애플리케이션은 `app` 라벨에 서로 다른 값을 사용하겠지만, [방명록 예제][github-k8s-examples-web-guestbook]처럼 다중 티어 애플리케이션은 추가로 각 티어를 구분해야 할 것이다.

아래 예시에서 `app` 라벨은 수동 쿼리와 간단한 CLI 사용을 위해 포함돼 있다. `app.kubernetes.io/name` 라벨은 권장되는 Kubernetes 라벨링 관례를 따르며 도구 사용과 자동화에 더 적합하다.

프론트엔드는 다음 라벨을 가질 수 있다:

```yaml
labels:
  app: guestbook
  app.kubernetes.io/name: guestbook
  tier: frontend
```

반면, Redis 마스터와 레플리카는 서로 다른 `tier` 라벨을 갖고, 심지어 `role` 라벨을 추가로 가질 수 있다:

```yaml
labels:
  app: guestbook
  app.kubernetes.io/name: guestbook
  tier: backend
  role: master
```

그리고

```yaml
labels:
  app: guestbook
  app.kubernetes.io/name: guestbook
  tier: backend
  role: replica
```

라벨은 라벨에 명시된 어느 차원으로든 리소스들을 나눌 수 있게 한다:

```bash
kubectl apply -f examples/guestbook/all-in-one/guestbook-all-in-one.yaml
kubectl get pods -Lapp -Ltier -Lrole
```
