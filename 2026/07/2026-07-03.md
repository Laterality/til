## 개요

### Kubernetes의 객체

#### Kubernetes 객체 이해하기

##### 필수 필드

생성하려는 Kubernetes 객체를 위한 매니페스트에는 다음 필드의 값을 설정해야 할 것이다:

- `apiVersion`: 이 객체를 생성하는 데 사용하고 있는 Kubernetes API 버전
- `kind`: 생성하려는 객체의 종류
- `metadata`: `name` 문자열, `UID`, 선택사항인 `namespace`를 포함해 객체를 유일하게 식별하는데 도움이 되는 데이터
- `spec`: 객체에 원하는 상태

객체 `spec`의 정확한 형식은 모든 Kubernetes 객체가 다르며, 객체에 특화된 중첩 필드를 갖는다. [Kubernetes API 레퍼런스][k8s-reference-kubernetes-api]가 Kubernetes를 사용해 생성할 수 있는 객체의 스펙 형식을 찾는데 도움이 될 수 있다.

예를 들어, Pod API 레퍼런스는 [`spec` 필드][k8s-reference-kubernetes-api-core-pod-v1-pod-spec]를 보면 된다. 각 파드에 대해, `.spec` 필드는 파드와 (파드 내의 각 컨테이너에 대한 컨테이너 이미지 이름과 같은)파드에 원하는 상태를 명시한다. 객체 명세의 또다른 예시는 StatefulSet API의 [`spec` 필드][k8s-reference-kubernetes-api-apps-stateful-set-v1-stateful-set-spec]다. 스테이트풀셋의 경우 `.spec` 필드는 스테이트풀셋과 이에 원하는 상태를 명시한다. 스테이트풀셋의 `.spec` 내부는 파드 객체의 [템플릿][k8s-concepts-workloads-pods-pod-templates]이다. 이 템플릿은 스테이트풀셋 컨트롤러가 스테이트풀셋 명세를 만족시키기 위해 생성할 파드를 기술한다. 서로 다른 종류의 객체는 서로 다른 `.status`를 가질 수 있다. API 레퍼런스 페이지는 이 `.status` 필드의 구조와 서로 다른 유형의 각 객체에 대한 내용을 상세히 설명한다.

YAML 구성 파일을 작성하기 위한 추가 정보는 [Kubernetes 구성 모범 사례][k8s-blog-2025-11-25-configuration-good-practices]를 참고하라.
