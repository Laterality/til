## 개요

### Kubernetes의 객체

#### 객체 이름과 ID

##### 이름

`/api/v1/pods/some-name`과 같이 리소스 URL에서 객체를 참조하는, 클라이언트가 제공한 문자열이다.

같은 종류(kind)의 객체는 한 번에 하나의 객체만 이 이름을 가질 수 있다. 하지만 이 객체를 삭제하면 같은 이름으로 새 객체를 생성할 있다.

이름은 같은 리소스의 모든 [API 버전들][k8s-concepts-overview-kubernetes-api-api-groups-and-versioning] 사이에서 유일해야 한다.

네 개의 속성 조합을 사용해 객체를 유일하게 식별한다:

- **API 그룹** (e.g., `apps`)
- **리소스 유형** (e.g., `deployments`)
- (네임스페이스에 속한 리소스인 경우)**네임스페이스**
- **이름**

(`v1` 또는 `v1beta1`처럼)서로 다른 API 버전으로 리소스에 접근하더라도 이 버전은 같은 객체에 대한 서로 다른 표현일 뿐이다. 버전은 유일한 식별의 일부분이 아니기 때문에 두 객체를 API 버전만 달리해 같은 이름, 같은 리소스 유형으로 같은 네임스페이스에 생성할 수 없다.

> [!NOTE]
>
> 물리적 호스트를 표현하는 노드와 같이 객체가 물리적 엔티티를 표현하는 경우, 호스트가 노드를 삭제후 재생성하지 않고 같은 이름으로 재생성되는 경우, Kubernetes는 새 호스트를 오래된 것으로 취급해 불일치를 유발할 수 있다.

서버는 리소스 생성 요청에 `name` 대신 `generateName`이 제공되면 이름을 생성할 수 있다. `generateName`이 사용되면, 제공된 값을 이름 접두어로 사용해 서버가 생성된 접미사를 뒤에 붙인다. 이름이 생성되더라도 기존 이름과 충돌해 HTTP 409 응답을 반환할 수 있다. 서버가 HTTP 409 응답을 반환하기 전에 최대 8번까지 유일한 이름을 생성 시도하기 때문에 이 문제는 Kubernetes v1.31 이후부터는 훨씬 덜 발생한다.

이후에는 리소스들에 널리 쓰이는 네 가지 유형의 이름 제약 사항을 설명한다.
