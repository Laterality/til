## 개요

### Kubernetes의 객체

#### 스토리지 버전

##### 커스텀 리소스의 스토리지 버전

[커스텀 리소스][k8s-concepts-extend-kubernetes-api-extension-custom-resources-storage]는 자기 스토리지 버전을 가진 내장 Kubernetes 타입과는 달리 동적으로 정의된다. 내장 객체는 일반적으로 자신의 API 유형과는 별개로 정의된 스토리지 인코딩을 가지며, 저장된 객체가 허브(hub)역할을 하기 때문에 객체 스키마의 필드라는 점 외에 리소스의 구체적인 버전은 중요하지 않다.

하지만, 커스텀 리소스의 경우 특정 버전의 리소스는 스토리지 버전으로 설정돼야 한다. 해당 버전의 커스텀 리소스로 정의된 스키마는 스토리지 계층에서 리소스의 인코딩으로 사용된다. API 셋업과 버저닝에 관한 더 자세한 정보는 [고급 CRD 기능 집합][k8s-concepts-extend-kubernetes-api-extension-custom-resources-advanced-features-and-flexibility]을 참고하라.

*crontabs*의 CustomResourceDefinition 예시:

```yaml
apiVersion: apiextensions.k8s.io/v1
kind: CustomResourceDefinition
metadata:
  name: crontabs.example.com
spec:
  group: example.com
  # list of versions supported by this CustomResourceDefinition
  versions:
  - name: v1beta1
    # Each version can be enabled/disabled by Served flag.
    served: true
    # One and only one version must be marked as the storage version.
    storage: true
    schema:
      openAPIV3Schema:
        type: object
        properties:
          host:
            type: string
          port:
            type: string
  - name: v1
    served: true
    storage: false
    schema:
      openAPIV3Schema:
        type: object
        properties:
          host:
            type: string
          port:
            type: string
          time:
            type: string
  conversion:
    strategy: None
  scope: Namespaced
  names:
    plural: crontabs
    singular: crontab
    kind: CronTab
    shortNames:
    - ct
```

`v1beta` API 정의가 스토리지 버전으로 쓰인다. 즉, `crontabs`의 모든 갱신이나 생성은 `v1beta1` API의 객체 스키마로 저장된다. 이 경우 `time` 필드를 저장하는 데 `v1` API 객체는 사용할 수 없다. 스토리지 정의의 일부가 아니기 때문이다. 이 스키마는 스토리지 계층에서 객체 자체의 바이너리 인코딩으로 쓰인다. 동시에 두 개 버전을 저장되는 버전으로 설정하려고 시도하는 것은 두 데이터 스키마가 동시에 객체를 저장하는 유효한 방법으로 간주된다는 의미이기 때문에 유효하지 않은 것으로 간주된다.

스토리지에 쓰이는 버전이 변경되면, 그 API 버전이 새 CR을 생성하거나 갱신하는 데 쓰인다. 객체를 감시(watch)하거나 조회하는 작업은 객체가 사용중이지만 이전 스토리지 버전에서 변환될 뿐이므로 객체에 영향을 주지 않는다. 오직 갱신이나 생성만 영향을 주며 새로 정의된 스토리지 버전을 사용한다.
