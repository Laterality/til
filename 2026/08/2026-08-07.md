## 개요

### Kubernetes의 객체

#### 어노테이션

##### 객체에 메타데이터 부착

라벨이나 어노테이션 중 하나를 사용해 Kubernetes 객체에 메타데이터를 부착할 수 있다. 라벨을 사용해 객체를 선택하고 조건을 만족하는 객체 컬렉션을 찾을 수 있다. 반면 어노테이션은 객체를 식별하거나 선택하는 데에 사용할 수 없다. 어노테이션의 메타데이터는 작거나 클 수도, 구조화돼 있거나 비구조화돼 있을 수 있으며 라벨에 허용되지 않는 문자를 가질 수 있다. 같은 객체의 메타데이터에서 라벨뿐만아니라 어노테이션도 사용할 수 있다.

어노테이션은 라벨처럼 키/값 맵이다:

```json
"metadata": {
  "annotations": {
    "key1" : "value1",
    "key2" : "value2"
  }
}
```

> [!NOTE]
> 
> 맵의 키와 값은 문자열이어야 한다. 즉, 키나 값 어느 쪽에도 숫자, 불리언, 리스트나 다른 타입을 사용할 수 없다.

다음은 어노테이션에 기록될 수 있을만한 정보의 예시다:

- 선언적 구성 계층에서 관리되는 필드들. 이러한 필드를 어노테이션으로 붙여 클라이언트나 서버에 의한 기본값, 자동 생성된 필드와 자동 수량 조정이나 오토 스케일링 시스템의 필드 집합과 구분한다.
- 빌드, 릴리즈 혹은 타임스탬프, 릴리즈 ID, git 브랜치, PR 번호, 이미지 해시및 레지스트리 주소와 같은 이미지 정보.
- 로깅, 모니터링, 분석 혹은 감사 저장소에 대한 포인터.
- 디버깅 목적으로 사용할 수 있는 클라이언트 라이브러리나 도구 정보. 예를 들면 이름, 버전, 빌드 정보 등이 있다.
- 다른 생태계 구성요소의 연관 객체 URL과 같은 사용자 혹은 도구/시스템 기원(provenance) 정보.
- 경량 롤아웃 메타데이터. 예를 들어 구성 혹은 체크포인트가 있다.
- 책임자의 전화번호 혹은 페이저 번호 혹은 팀 웹사이트처럼 정보가 명시된 디렉토리 엔트리ㅣ.
- 구현체의 동작을 바꾸거나 비표준 기능과 접촉하기 위한 최종 사용자로부터의 지시자.

어노테이션을 쓰는 대신 외부 데이터베이스나 디렉토리에 이런 유형의 정보를 저장할 수 있지만 이는 배포, 관리, 조사 등과 같은 공유 클라이언트 라이브러리와 도구를 만들기 훨씬 어렵게 만든다.
